# AGENTS.md — Grow Codes SDK for Datadog Log Management (`datadog-logs`)

Instructions for AI coding agents and humans working in this repository. `CLAUDE.md` is a symlink to
this file. Service-specific notes (vendor quirks, API coverage, emulator limits) live in
`docs/compatibility.md`, the README "Function overview" and `skills/datadog-logs-sdk/SKILL.md`.

## What this repository is

One API for Datadog Log Management in five languages, generated from
[sdk-kit](https://github.com/grow-codes-packages/sdk-kit) (version in `.sdk-kit.json`) and
completed with service code. Categories: **logging**. The contract for every package is the
sdk-kit specification (`SPEC.md` in sdk-kit): names, defaults, error codes, environment variables,
category interfaces and the Docker contract.

## Generated files rule

- A file whose first lines contain `Generated by sdk-kit <version> — do not edit` belongs to sdk-kit.
  **Do not edit it here.** Change sdk-kit (template), release it, then run `sdk-kit sync` in this
  repository. A local edit is detected (`.sdk-kit.json` keeps a SHA-256 per file) and blocks the
  next sync until it is reverted or forced.
- To take over a generated file for good, delete its header line; sync then leaves it alone.
- Never edit `conformance/` or `.sdk-kit.json` by hand.
- `sdk-kit check` (run in CI) verifies that the required files, badges and workflows are present.

## API parity rule

The five packages expose the **same** functions, options, defaults, error codes and behaviour. Any
change to the public API lands in all five languages in the same pull request, with unit tests in
each and an integration call in the Docker suite. Names follow each language's convention:

| | TypeScript | Rust | Go | Python | Java |
| - | - | - | - | - | - |
| Methods | `camelCase` | `snake_case` | `PascalCase`, `ctx` first | `snake_case` | `camelCase` |
| Errors | `DatadogLogsError` + subclasses | `Error` enum, `code()` | `*Error`, `errors.Is(err, datadoglogs.ErrNotFound)` | `DatadogLogsError` + subclasses | `DatadogLogsException` + subclasses |
| Durations | `…Ms` numbers | `Duration` | `time.Duration` | seconds (`…_s`) / `timedelta` | `Duration` |
| Async | `Promise` + `AbortSignal` | `async` + `blocking` feature | sync with `ctx` | sync + `AsyncDatadogLogsClient` | sync + `…Async` |

If one language truly cannot support something, document it in `docs/compatibility.md`.

## Tests and coverage

- Unit tests run against local mock HTTP servers; they never need network access or Docker.
- **Coverage gates** (CI-enforced, first-party code only): TypeScript, Python and Java ≥ 90 % lines
  **and** ≥ 90 % branches; Rust ≥ 90 % lines and ≥ 90 % regions; Go ≥ 90 % statements.
- Unit conformance tests are named after the ids in `conformance/core-unit.md`.
- Test fakes for users of the package ship in the testing module (TypeScript
  `@grow-codes/datadog-logs/testing`, Rust feature `testing`, Go `testkit`, Python
  `grow_datadog_logs.testing`, Java `codes.grow.packages.datadoglogs.testing`).

## Docker integration rules

- `docker/compose.yml` runs `datadog/fakeintake:v79` (pinned by digest in `docker/compose.service.yml`) plus a one-shot `bootstrap` service that writes credentials
  to `/bootstrap/env`. Tests read that file and `GROW_DATADOG_LOGS_URL`.
- Each language has a `test-<lang>` service (profile `<lang>`). Its Dockerfile packs the package and
  installs it into the consumer project in `<lang>/integration/`, which runs the integration tests
  and the conformance runner.
- Always run through `make test-docker`: it uses a unique Compose project per run, publishes no host
  ports and always runs `docker compose down -v`, even on failure or Ctrl-C.
- Every public function is called at least once against the real service with a round-trip
  assertion. Functions the service cannot serve are listed in `docs/compatibility.md` and covered by
  unit tests.

## Release rules

- Releases are made by [release-please](https://github.com/googleapis/release-please) from
  Conventional Commits on `main` (`feat:`, `fix:`, `feat!:`). Never bump versions or edit
  `CHANGELOG.md` by hand. Use the language as the scope when a change touches one package.
- One release pull request covers all five packages. Tags: `typescript-vX.Y.Z`, `rust-vX.Y.Z`,
  `go/vX.Y.Z` (the Go module lives in `go/`, so its tag must be `go/v…` for `go get` to work),
  `python-vX.Y.Z`, `java-vX.Y.Z`.
- The release workflow publishes to npm, crates.io, PyPI and Maven Central; Go is published by its
  tag. Publishing credentials live only in the release environment of the GitHub repository.

## Datadog Log Management specifics

- **Service modules** (service code in every language): config + site resolver, client
  (`health`/`ping`/`validateApiKey` on `/api/v1/validate`, `serverVersion` → `UNSUPPORTED`),
  intake exporter + mapping, `logClient`, query client (`searchLogs`, `iterateLogs`,
  `aggregateLogs`, `listIndexes` + the `LogQueryClient` methods `search`, `tail`, `waitForLog`,
  `listStreams`, `listLabels` → `UNSUPPORTED`). File map: TypeScript
  `src/{client,config,sites,http,exporter,mapping,query}.ts`; Rust
  `src/{client,config,http,intake,mapping,query,blocking}.rs`; Go
  `{client,config,datadog_errors,intake,query,aggregate,tail}.go`; Python
  `src/grow_datadog_logs/{client,config,sites,_datadog_http,exporter,mapping,query}.py`; Java
  `codes.grow.packages.datadoglogs.{DatadogLogsClient,DatadogLogsConfig,DatadogHttp,DatadogLogExporter,DatadogLogMapping,DatadogLogsQuery,…}`.
- **Binding decisions** (keep all five languages on them; full list in `docs/compatibility.md`):
  - Env: `GROW_DATADOG_LOGS_*` > `DD_API_KEY`, `DD_APP_KEY`/`DD_APPLICATION_KEY`, `DD_SITE`,
    `DD_SERVICE`, `DD_ENV`, `DD_VERSION`, `DD_TAGS`, `DD_HOSTNAME`. API key required; the app key is
    only sent to the query API.
  - Every Datadog 403 → `AUTHENTICATION` (status 403 kept).
  - Every Datadog request (intake POST included) is retried on 408/429/5xx/network;
    `X-RateLimit-Reset` is the retry hint on 429 **and 503** when `Retry-After` is missing.
  - `dd.trace_id`/`dd.span_id` = decimal lower 64 bits (same rule as datadog-apm);
    `otel.trace_id`/`otel.span_id` = full hex.
  - Intake limits enforced client-side: 1,000 entries / 5 MB per request, 1 MB per log (truncate
    the message, `grow.truncated=true`); reserved names in user attributes → `attr.<name>`;
    `ddsource` default `grow-sdk`; `ddtags` replaces whitespace and commas inside a tag with `_`.
  - `aggregateLogs` always sends compute `type` (`total` by default).
  - `tail` is a polling search (start default now, interval 5 s); `waitForLog` 5 s / 30 s;
    `listStreams` = index names.
  - Calls on a closed client raise `CANCELLED` (TypeScript wraps the generated transport, which
    says `CONFIG`).
- **Wire traps**: error bodies are lists of strings (`{"errors":["Forbidden"]}`), no request-id
  header; a 200 search/aggregate answer without `data` is a protocol error (`UNAVAILABLE`), never
  an empty result (fakeintake answers 200 `{"errors":[]}` to un-stubbed routes).
- **Docker**: `bootstrap/` overrides `POST /api/v2/logs` to answer 202 `{}`, stubs
  `GET /api/v1/validate` with `{"valid":true}` and writes `/bootstrap/env` (placeholder
  `DD_API_KEY`/`DD_APP_KEY`, `GROW_DATADOG_LOGS_URL`/`_INTAKE_URL`/`_API_URL`, `FAKEINTAKE_URL`).
  Read captured payloads from the raw view `/fakeintake/payloads?endpoint=/api/v2/logs` (the typed
  view breaks on object bodies). Query functions run against `/fakeintake/configure/override`
  stubs; overrides cannot set headers.
- **Live job**: a run against a Datadog sandbox organisation is planned and waits for owner keys.
- Language differences (poll interval defaults in Rust/Java option types, Python `from_env`
  positional-only mapping and `dataclasses.replace`, Python async tail cancellation): see
  `docs/compatibility.md`.

## Rules for agents

- Keep secrets out of code, tests, fixtures, logs and commit messages. Credentials are always wrapped
  in the redacting secret type; error messages pass through redaction.
- Runtime dependencies must use a licence from the allowlist: Apache-2.0, MIT, BSD-2-Clause,
  BSD-3-Clause, ISC, Zlib, Unicode-3.0, Unicode-DFS-2016, 0BSD, CC0-1.0, MPL-2.0. Never GPL, LGPL,
  AGPL, SSPL, BUSL or EPL at runtime.
- Keep dependencies small; prefer the standard library.
- Before you push: `make lint coverage` for every language you touched (or all of them for shared
  changes), and `make test-docker LANGS="<lang>"` when behaviour against the service changed.
- Update the README function overview, `docs/` and the skill file when the public API changes.
